# G69

**O240 (half) recurring schedule with no fires left no longer wraps to unlimited (2026-11-08)**

`MessageScheduler.fireOne` computed `if (remaining < 0) -1 else remaining - 1`, so a recurring row with `remainingFires = 0` (the `ScheduledMessage` default) became −1 = fire forever, and every negative was treated as unlimited.
Now only exactly −1 is unlimited; any other count that reaches ≤ 0 deletes the row after its fire.
`scheduleRecurringBroadcast` requires `count > 0 || count == -1`.
`MessageSchedulerTest` +2 (rows with 0 and −5 inserted straight into the repo — bypassing the compose-side check — fire once and are deleted;
count 0 refused at scheduling); the existing unlimited-recurrence test is the discrimination control; teeth-verified. Latent:
no `:app` caller schedules recurring messages yet. O240 stays open for fire atomicity and failure state. ELI5 `docs/handoff/eli5/SESSION_ELI5_2026-11-08.md` §1.
