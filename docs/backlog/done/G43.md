# G43

**O126 HLC SharedPreferences Int→Long upgrade crash (2026-07-22) — 0.6.9-hlc-prefs-guard (vc30), field-verified same day**

Filed by the 2026-07-19 audit (§17), hit in the field three days later exactly as predicted:
the OnePlus (which had run an intermediate build that wrote the HLC counter with `putInt`) crashed with `ClassCastException:
Integer cannot be cast to Long` on every `startMesh()` after the vc29 in-place install — unlock-triggered, looked like a random new bug, invisible to fresh installs/tests.
Fix:
MeshService's `HlcStore.load` reads defensively — try `getLong`, on `ClassCastException` fall back to `getInt`, coerce, rewrite the key as Long so the fallback runs once per key.
Field-verified against the same poisoned prefs:
0.6.9 installed in-place, unlock started the mesh cleanly, phone immediately exchanged with the `:node` laptop instance over LAN (overlap converged to 1.0).
**Rule going forward: never change the stored type of an existing SharedPreferences key — bump the key name instead (or guard the read).**
