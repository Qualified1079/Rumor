# G18

**First real two-device exchange (field-tested Moto G Play 2024 + OnePlus CPH2515, both API 34)**

Five stacked bugs, each masking the next, fixed and verified live:
(1) `enqueueCommand` was a try-acquire that silently dropped the connect command whenever it landed inside the previous command's 300ms settle window — replaced with a real FIFO drained on the main handler;
(2) `connectAttemptInFlight` latched forever because a failed GO negotiation emits no CONNECTION_CHANGED broadcast — added 45s watchdog;
(3) the device-address GO tiebreak was inert:
API 29+ anonymises our own P2P MAC to `02:00:00:00:00:00` in THIS_DEVICE_CHANGED, so both sides always initiated — now falls back to randomised `groupOwnerIntent` (0–14) when no real local address is available;
(4) **wire-protocol deadlock**:
the MESSAGE phase had no terminator, so both receive loops blocked waiting for the peer's ACK, which each peer only sends after its own loop exits — every exchange timed out at 30s, always;
added `MESSAGES_DONE` frame + restructured the tail (each side sends ACK/ONLINE_STATUS/BYE without waiting, then reads the peer's);
(5) `peerNearbySignal` is a level not an edge, so colocated devices gossiped exactly once — MeshService now runs 15s gossip rounds while the signal holds. Also:
contacts are now created from a completed exchange (`GossipEngine.onExchange` → `MessageStore.ensureContact`) since HELLO challenge-response is stronger provenance than a relayed message signature, and a zero-message exchange must still produce a contact.
Verified end-to-end: discovery→GO(asymmetric)→TCP→HELLO→session ~90–130ms, contact on both sides, broadcast delivered, dedup overlap=1.00 next round.
Effective round period is ~60–70s (full teardown+renegotiation each round) — O2 priority links are the path to instant delivery.
