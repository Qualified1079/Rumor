`core/model/KeywordFilter.kt:136-156` transcript is `publisherId | version | name | <entries> | <allowlist>` with bare `|`/`:`/`,` around unvalidated free text — `name` and `entries[].pattern` can contain `|`, so anyone who observed one legitimately-signed list can craft a different `(name', entries', allowlist')` with a byte-identical transcript (shift content across the `name|entries` or `entries|allowlist` boundary via an embedded `|`), reuse the original `list.signature` untouched, and rebroadcast under their own outer sig.
`KeywordFilterVerifier.verify` resolves the pubkey from the subscriber's own pinned record, not from the object being verified — so it verifies. Impact:
silently changes what gets BLOCK/WARN'd for every subscriber, or drops someone from `userIdAllowlist`, while the UI shows "validly signed by a trusted publisher." No private key needed.
`BlockManager.block()` already closed the identical risk (gates through `CryptoManager.isValidUserId`) — not done here.
