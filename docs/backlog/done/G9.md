# G9

**O41 identity rotation — REMOVED entirely**

Originally added in commit `21f024b` as `MessageType.IDENTITY_ROTATION` with `IdentityRotationPayload` (oldUserId, newUserId, newPublicKey, authorizedAtMs, continuitySignature), `GossipEngine.composeIdentityRotation`, `ContactRepository.rebindIdentity`, and auto-rebind receive logic.
**Removed entirely** because the auto-rebind UX turns key-compromise into permanent impersonation — attacker with stolen old key signs a rotation to their own new key, every contact auto-rebinds to attacker's userId, victim is taken over to everyone they knew.
No deployed users to maintain wire compat with, so full removal was the cleanest path.
Wire-type name `"identity_rotation"`, payload class `IdentityRotationPayload`, KDF tag `rumor-identity-rotation-v1:`, and method `ContactRepository.rebindIdentity()` are reserved forever in `docs/RENAMED_FIELDS_NEVER_REUSE.md` — never reused.
Deletion-announcement use case moved to O69 (signed `IDENTITY_RETIRED` broadcast, no successor key — safe because there's nothing to be hijacked into).
If clean device-change identity transfer becomes a real need later, design a manual-confirm-by-recipient flow (recipient sees a notification, makes a choice) rather than auto-rebind.
