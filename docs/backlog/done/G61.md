# G61

**O220 `awaitUntil` timed out silently — the sim suite's precondition gate was faking itself (2026-10-11)**

The shared sim wait helper returned silently when its condition never held, by design ("the caller's own assertion then reports the failure state").
That reasoning only holds where the awaited condition IS the asserted property;
at most of its ~30 call sites it is a PRECONDITION, and a silent timeout ran the rest of the test against a state it was never written for. Two measured costs:
`PerPeerRoutingTest` failed 2 of 4 runs on an UNMODIFIED tree (different sub-assertion each time, none the property under test), and `SelfEchoTest` was **vacuous** — it awaited A's beacon landing in B's *repo*, but `handleSelfPresence` ingests SELF_PRESENCE with `persist = false` by design, so that condition could never hold;
it timed out every run and then asserted "A's own id is absent from A's view" against a mesh where the beacon had never moved, an absence that holds whether the self-echo guard exists or not.
**It would have passed with the guard deleted.** Now:
timeout throws and names the subject (`what = "…"`), default budget 3 s → 10 s (a passing wait costs only what the effect takes), condition is `suspend` so it can read a repository.
`TestAwaitTest` is the teeth check for the check.
`SelfEchoTest` rewritten to await the dedup set and assert two positive controls first (B really PROCESSED the beacon; B really OFFERS IT BACK).
Both rules written into `docs/SIMULATOR_TESTING.md`.
