# G75

**O166 Accept loop caps pre-HELLO concurrency. **Resolution:** `admitInbound` reserves a total slot (`MAX_INBOUND_INFLIGHT=32`) + a per-source-IP slot (`MAX_ (DONE 2026-08-01; archived 2026-11-08)**

`core/transport/lan/LanTransport.kt` `start()` (~113-117) accepts unbounded concurrent inbound `GossipSession`s in a `while (isActive)` loop with no per-IP rate limit and no inflight cap.
The `sessionGate` dedup (first-come-wins per verified peer userId) only kicks in AFTER HELLO completes, so it doesn't bound pre-verification crypto cost.
Matters more than for Wi-Fi Direct (whose ~8-10 GO-client cap is a natural ceiling a regular AP lacks) — and O104's `:node` intent is literally "the laptop IS the AP," so any device that associates can reach this port and force Ed25519-verification work per connection at zero attacker cost.
Fix: cap total inflight sessions + per-source throttle before HELLO. Cross-ref O104, O107, O43.
