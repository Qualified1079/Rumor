# G71

**O144 Signature-transcript canonicalization — v2 length-prefixed framing (splice attack closed; filed + fixed 2026-07-23 from the parallel audit, user-appro (DONE 2026-07-23; archived 2026-11-08)**

**`MessageStore.signableBytes` concatenates `id+senderId+senderPublicKey+sequenceNumber+sentAtMs+type.name+content+encryptedPayload+recipientId` with ZERO separators.** `senderId==SHA-256(pubkey)` protects the identity fields, but the trailing free strings (content/encryptedPayload/recipientId) are freely re-partitionable:
a relay can move a signed broadcast's content suffix into `encryptedPayload` — byte-identical concatenation, so the sender's signature still verifies, but the displayed content (which reads only `payload.content`) is now **truncated** (e.g.
"Evacuate at 9pm, NOT before" → "Evacuate at 9pm", validly signed). A real integrity break in the core auth scheme.
**PARTIAL FIX SHIPPED 2026-07-23 (non-wire):** `MessageStore.ingest` now drops (a) any message whose `recipientId` isn't null-or-64-hex (`CryptoManager.isValidUserId`), and (b) any BROADCAST carrying `encryptedPayload`/`recipientId` — closes the demonstrated broadcast-truncation + the recipientId-splice without a wire bump (every legit `composeX` path satisfies both;
verified + tested in `MessageStoreIngestTest` with a real splice whose sig genuinely verifies).
**REMAINING — needs a user decision (wire-format-affecting):** the proper fix is a length-prefixed canonical transcript (`len:field` per field, not a bare delimiter which is itself forgeable) under a `rumor-msg-v1:`→`v2:` domain-tag bump, back-ported to the newer `'|'`-delimited helpers too.
This changes the signed bytes → needs a coordinated fleet update + a transition decision (dual-verify v1&v2 during a window vs hard cutover — the fleet is on 0.6.13, all test devices, no shipped users).
**Do not cut over the signing format without the user's call.** Cross-refs O65 (two wire layers), O112 (isValidUserId), `docs/RENAMED_FIELDS_NEVER_REUSE.md`.
**REAL FIX SHIPPED (`0.6.14-o144-sigv2`, vc35):** `signableBytes` now writes each field as `<charLen>:<value>` (self-delimiting / prefix-free) under a `rumor-msg-v2:` domain tag — no two distinct field-sequences can share a transcript, so the splice is structurally impossible (test:
the truncation splice's signature no longer verifies under v2). Hard cutover, no shipped users;
v1 retired in `RENAMED_FIELDS_NEVER_REUSE.md` + wire-format.md §3.2/§6.
Two stale hand-copied `signableBytes` duplicates (RbsrSimTransportTest, MessageGenerator) found + fixed to delegate to the real function so they can't drift again.
The `'|'`-delimited newer helpers assessed splice-safe (fields are hex/base64/decimal/enum, can't contain `'|'`) — deliberately not re-framed.
Belt-and-suspenders ingest shape guards (broadcast-must-not-carry-encryptedPayload, recipientId null-or-64hex) kept.
**Fleet must reflash to `0.6.14` to interoperate** (v1 and v2 signatures never cross-verify — by design).
