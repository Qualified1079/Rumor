# G35

**O39 per-message key lifecycle audit**

Audit traced the per-message X25519 + AES key path through `composeDirect` (sender), `MessageStore.ingest` (relay/store), and `ThreadViewModel.decryptPayload` (recipient read).
**Findings + fixes:** (a) **Sender ephemeral private and derived AEAD key now actively zeroed.** `composeDirect` calls `ephemeral.privateKeyBytes.fill(0)` and `sharedKey.fill(0)` immediately after the AES-GCM call;
before this, both bytes sat on the heap until GC, recoverable from a process-memory dump in that window.
(b) **Recipient AEAD key zeroed in `decryptPayload`** via `try/finally` so a tampered ciphertext throwing in the AEAD path still triggers the zeroize.
The recipient's long-term X25519 static (`localPrivKey`) is owned by `IdentityManager` and outlives the call — the audit explicitly does not touch it (per-message FS doesn't apply to the long-term key;
that's O38's domain).
(c) **No AEAD-key caching anywhere.** Every DM read re-derives `sharedKey` from `(senderEphemeralPub, recipientStaticPriv)`, decrypts, displays, drops.
Plaintext is NOT cached at-rest on the recipient — this is the "good" branch of O39's two options.
(d) **No ephemeral-private retention beyond `composeDirect`.** The returned `RumorMessage` contains only the ephemeral pub (in `encryptedPayload`);
the ephemeral priv never leaves the function.
(e) **Sig-scope confirmed correct.** `MessageStore.signableBytes` signs `encryptedPayload` (ciphertext + ephemeral pub), never plaintext — closes the Bridgefy surrogate-signature / UKS attack class.
(f) **One observation, not yet fixed:** the sender's long-term Ed25519 `privateKeyBytes` is held in `LocalIdentity` for the unlocked-session lifetime;
signing path uses it directly via `CryptoManager.sign`. Not zeroed because it's the identity key — needed for every outbound message.
The leakage surface is bounded by `IdentityManager.lock()` which zeroes the StateFlow value.
**Test guard:** `SourceInvariantTest` adds a fourth invariant (regex-checks the two `.fill(0)` calls exist in `composeDirect`) — same brittle-by-design pattern as the BRIDGED / BRIDGE_UNSIGNED / dedup guards.
A refactor that silently drops the zeroize trips the test.
