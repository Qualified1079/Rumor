# G82

**O138 Kill the reflash+manual-unlock loop for dev/test (DONE 2026-07-22 — 0.6.11; archived 2026-11-08)**

Every code change to `:app` currently needs `adb install -r` (fine, preserves data) **+ a manual on-screen unlock** (the real pain — a human must touch each phone, and identity is passphrase-locked after the process restart).
Fixes, cheapest first:
(a) **debug-only auto-unlock** — in a `BuildConfig.DEBUG` build, auto-unlock an existing identity with a dev passphrase on start (fleet passphrase is already `passphrase1`, recorded in memory;
test devices only) OR (b) **adb-triggerable unlock** — a debug `BroadcastReceiver` that unlocks on `adb shell am broadcast … --es passphrase …` (keeps the secret out of the APK, still hands-free).
**SHIPPED (a):
`MainActivity.onCreate` debug auto-unlock, hard-gated `BuildConfig.DEBUG`, passphrase `passphrase1`, verified hands-free on all 3 phones (flash + `am start` → auto-unlock → mesh, no manual step).** Future reflash = `adb install -r` + `am start -n com.rumor.mesh.debug/com.rumor.mesh.MainActivity`.
Unblocks O137's synthetic fleet and every multi-device test. Also reduce reflash *frequency*:
prefer putting instrumentation in `:node` (no reflash) over `:app` when a choice exists;
core-only changes still need a rebuild but the node picks them up on restart. **Never ship either path in release** — gate hard on `DEBUG`.
