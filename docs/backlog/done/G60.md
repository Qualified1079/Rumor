# G60

**O219 routed DM withheld from its own recipient (2026-10-11)**

`relay()` marked a routed DM `intendedPeers = <breadcrumb candidates>` and the serve path hard-excludes any peer outside that set, so a relay holding a DM for A, with A present as a direct peer, did NOT offer it to A whenever its crumb for A named some other node.
Hidden because the store-backfill re-offer path re-derives the same restriction but explicitly allows the recipient (`msg.recipientId != peerUserId`) — so A eventually got it, which made the bug look like delay and made the test outcome depend on whether the marked copy was still queued when the recipient was offered to (a 1-in-3 flake rather than a visible failure).
Not mere delay under O55: a duty-cycled node's contact window may be its only one for hours. Fix:
union the recipient into the routed candidate set at relay time so both paths agree.
`RoutedDmReachesRecipientTest` pins the adversarial shape (B's only crumb for A names D, not A), offers to the recipient FIRST while the marked copy is queued, asserts the offered copy is the ROUTED one so it cannot pass via an unrouted store copy, and keeps the control that matters:
the sender C, neither recipient nor crumb candidate, must STILL be excluded — if that ever passes the DM, `intendedPeers` has stopped restricting anything.
Verified to fail without the one-line fix. **Found by root-causing a flaky test instead of re-running it.**
