**O232 (half) TRANSFER_CANCEL bound to the transfer's receiver (2026-11-06)**

`TransferSender.onTransferCancel` only required the cancel to be addressed to us, so any node could stop resends of our transfer;
on a broadcast transfer any one receiver stopped them for everyone. Now the record must be SENDING and the canceller must be its `recipientId`;
for a broadcast transfer (`recipientId == null`) the cancel opts out only that receiver (`optedOutReceivers`, checked in `handleChunkRequest`) and the transfer stays IN_PROGRESS.
Tests: `:core` `TransferSenderTest` (+2: non-receiver ignored with the real receiver still served;
broadcast opt-out with another receiver still served) and `:simulator` `TransferSenderTest` (+1:
genuinely signed forged cancel over real transport, positive control that it arrived, real receiver's NACK still served;
the existing real-receiver cancel test is the discrimination control). Teeth-verified: with the binding removed, exactly the 3 new tests fail.
O232 stays open for the send-side COMPLETE/leak half. ELI5 §3.
