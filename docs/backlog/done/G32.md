# G32

**O64 `sentAtMs` untrusted-everywhere**

(a) `RumorMessage.displayTimeMs = min(sentAtMs, receivedAtMs)` extension in `core/model/Message.kt` — UI ordering and "X ago" labels consume it.
(c) Every direct `.sentAtMs` reference audited;
only compose-time stamps, the Ed25519 signature payload, Room/wire adapters, bridge plugins setting foreign-network timestamps, simulator + RBSR ordering keys, and test fixtures access it directly — every site is documented in `SentAtMsLintTest`.
The lint guard fails on any new direct access outside the explicit allowlist.
(d) UI sites — `FeedScreen`, `ThreadScreen`, `MessagesScreen`, `MessagesViewModel` — consume `displayTimeMs` or `receivedAtMs` (whichever fits) instead of raw `sentAtMs`, closing the message-pinning attack.
(b) Explicit ingest-time clamp was considered and rejected as redundant:
`displayTimeMs = min(...)` handles future-forging implicitly, and clamping the signed `sentAtMs` field on the relay path would invalidate the Ed25519 signature.
