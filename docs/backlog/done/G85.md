# G85

**O254 own room messages are stored, so every peer is offered them, not only the first (2026-11-11)**

Found live on a three-node :node line A-B-C: B's room post reached C and never reached A.
composeBroadcast and composeDirect store what they compose (ingestOwn);
the four room composes only enqueued to the scheduler, whose take() is destructive, so whichever peer opened a session first drained the message and the store backfill had nothing to offer the next peer.
Same defect for a creator's own ROOM_CREATE, invites and actions, which also vanished on restart. Sibling of the relayed-copy fix in 6e918c0.

Fix: GossipEngine's composeRoomCreate/Invite/Action/Message store the composed message. Test:
OwnRoomMessagesReachEveryPeerTest (broadcast control passes before and after; post, create and invite were red before).

Also fixed in the same change: composeRoomInvite now refuses a banned user.
Receivers already dropped such an invite, so composing it added the user to the moderator's roster alone and the moderator disagreed with the rest of the room about membership (seen live).
RoomLifecycleTest's ban-outranks-invite case now drives the receive side from a second engine holding the moderator key, since the creator's engine refuses to compose it.

Not covered: composeDirectAck has the same shape (filed separately).
