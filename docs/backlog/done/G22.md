# G22

**Three-node mesh + first multi-hop relay (Moto G Play + OnePlus CPH2515 + Samsung S10e/API 31)**

Two bugs surfaced the moment a third device joined, then the core promise worked. (1) CONNECTION_CHANGED re-fires on every group-membership change;
the GO re-ran `startServerSocket()`, killing the live accept loop mid-rebind, and clients stacked duplicate round loops — both now guarded (keep a healthy server socket;
one `clientLoopJob`). (2) `claimSession`'s direction tiebreak ("lower userId keeps outbound") assumed both directions exist;
in a GO↔client group only the client dials, so whenever the comparison favored the impossible direction both sides vetoed the only session — endless HELLO retries.
The two-phone pair had only worked because its userIds happened to align with roles.
Now first-come-wins per peer (a true dual-role double-connect can't occur today — nothing dials into a non-GO).
**Verified end-to-end:** star topology (Oppo GO, Moto + Samsung clients, interleaved ~100ms sessions every 10s round);
broadcast relayed Moto→Oppo→Samsung in 7s (Samsung had never completed a session with the Moto); next-round `overlap=1.00` (no duplicate re-send).
Samsung also exercised the previously-untested `wifiDirectDualRoleRequired` branch and the pre-Tiramisu ACCESS_FINE_LOCATION path — both work.
