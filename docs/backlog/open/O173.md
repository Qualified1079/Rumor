# O173

**`[MEASURED 2026-10-11 — DECISION NEEDED]`** `PersistencePlanner`/`MeshViewTracker` has no sybil resistance on self-declared `UserMode.FREE` capacity

**Quantified** (`PersistencePlannerSybilBiasTest`, pure `:core`, deterministic). 20-node MOBILE ring, redundancy=2:
1 declared-FREE sybil takes 8 honest link slots and fragments the honest-only backbone into 4 components; 3 sybils → 24 slots / 12 components;
**8 sybils → 40 slots, zero honest-honest links, all 20 honest nodes isolated at the persistence layer.** Control:
the same 8 identities declaring MOBILE take 2 slots and leave the backbone spanning (1 component) — the self-declared mode is the lever.
Mixed realistic shape (1 honest FREE anchor + 1 sybil FREE):
both fill capacity 8, honest backbone → 9 components if the sybil defects, so the mechanism is **dilution of honest budget, not competition for hub rank**.
Tested and REJECTED: userId-grinding for `plan()`'s lexicographic tie-break buys nothing (honest capacity isn't scarce enough for ties to bind).
**Second finding:
claims need no reciprocity** — `assembleView` keeps an edge whenever the *named* endpoint is a known beaconing node, so a sybil that has never been in radio range of anyone gets all 20 of its claims into the view and the planner turns them into real link assignments, contradicting that function's own KDoc ("a link both endpoints could realize", "a one-sided edge can't converge").
Control: an edge naming a never-beaconed node IS still dropped.
**Scope caveats (do not over-quote):** this is the O98 persistent-link layer, NOT message delivery — opportunistic gossip is unaffected;
and the all-MOBILE ring is a worst case for *population* (the tracker is fed only by SELF_PRESENCE, and MOBILE has `presenceBeaconIntervalMs = null`, so a real view is mostly anchors + recently-pulsed phones).
**Why no fix shipped — the structural obstacle:** the obvious mitigation (rank by observed relay history / first-hand exchange) breaks the planner's one hard property, agreement without a coordinator — `plan()` must be a pure function of a SHARED view so both endpoints of a planned edge independently agree to hold it, and first-hand evidence is per-node, so A and B would compute different plans (the O99 self-election fragmentation).
**The three candidates, for the user's call:** (a) **require reciprocity** — an edge counts only if both endpoints' signed beacons name each other;
kills the unilateral variant outright, determinism-preserving, cheap; does NOT stop a sybil that really is nearby;
costs a new honest anchor a beacon round before it can be recruited.
(b) **local clamp** — a node spends at most ⌊cap/2⌋ of its own budget on peers it has no first-hand history with;
must be applied as a LOCAL clamp AFTER the shared plan, never inside the ranking, or it fragments.
(c) **earned capacity** from attested relay history — biggest change, and it penalises exactly the fresh honest anchor O54/O104 wants to recruit;
belongs with O135/O136 bootstrap-trust. (a)+(b) is the plausible pair. Cross-ref O127, O98, O135, O136, O137, O54/O104. — orig: | `core/routing/PersistencePlanner.kt:42` — a single fresh keypair can claim FREE capacity and bias honest nodes' backbone-hub selection toward itself.
