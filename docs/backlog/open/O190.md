# O190

**`[TODO/EMU]`** Ephemeral / RAM-only mode — tiered scale-of-forgetting (filed 2026-07-30, privacy workshop)

Option to keep identity + message store only in memory, never on disk — strongest privacy primitive is nonexistence (same logic as O38's deleted prekey).
NOT one switch but a scale: persist-across-reboot (default) → **lose-on-reboot** → **lose-on-app-close** → lose-on-battery-death (the involuntary reboot case).
Only difference between tiers is WHEN the vault key is discarded.
**Seam already exists:** `:simulator`'s in-memory repos (now `core/data/memory/InMemoryRepos.kt` per O106) are a complete in-memory backing for every repo;
ephemeral mode = wire those + `Room.inMemoryDatabaseBuilder` instead of Room-on-disk. The catches are all AROUND the DB, where ephemerality actually leaks:
no SQLite WAL/journal on disk, no logcat content leak, keyboard cache, and Recents/screenshot (makes O165 FLAG_SECURE non-negotiable in this mode);
Android may still spill process memory to **zram** (compressed swap) — unpreventable at the app layer, disclose honestly. Interaction with O191:
ratchet state can't survive restart in the app-close tier → ephemeral mode resets ratchets → conversations silently re-run X3DH on next contact (compatible, must be designed).
UX landmine — opt-in, loudly labeled ("nothing survives"). Cross-ref O38, O165, O191, O106, O189, O55.
