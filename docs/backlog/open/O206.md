**`[TODO/CODE]` `[STRUCT-adjacent]`** Socket-level persistent connections for static/infra nodes (filed 2026-08-06, from the per-round-reconnect discussion)

`LanTransport.runRound` opens a **fresh TCP socket every `ROUND_INTERVAL_MS` (10s)** and re-runs the full HELLO Ed25519 challenge-response each round, even for a backbone peer the O98 planner said to "hold a persistent link to." That per-round reconnect is the CORRECT default for battery phones under O55 (sleep between sync bursts;
self-heal on churn; a peer that restarts gets a new ephemeral port and the re-resolve handles it).
But it is wasteful on an **always-on, wall-powered node** (O104 "laptop IS the AP", O54 transport-plugin tier), where holding the connection open would (1) amortize the per-round handshake+signature-verify CPU, (2) cut delivery latency (push a new DM immediately vs waiting for the next round), and (3) give an **exact liveness signal** (socket open = reachable now) that makes O198's window-based `isRecentlyExchanged` unnecessary on those nodes.
**Scope:** gate socket-level keep-open on STATIC/infra `UserMode` (mobile stays per-round);
optional middle rung even on mobile = "keep-warm while actively exchanging, drop on idle." Note the O98 `PersistenceCoordinator` already does the *link-selection* half ("which backbone peers to hold persistent links to") — this is the missing *socket* half.
Respect O145 (transport code is field-verified — additive, gated, don't disturb the per-round path).
Cross-ref O98, O104, O54, O107 (Transport SPI), O198 (liveness signal), O94 (HELLO-timeout churn).
