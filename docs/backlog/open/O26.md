**`[TODO/CODE]`** Community attestation and peer plugin sharing**

No central plugin repository.
Plugin publishers broadcast a signed metadata record on the mesh (`pluginId`, `version`, name, description, capability list, `SHA-256(bundle)`, size).
Reviews are **separate** signed messages anchored to `(pluginId, bundleHash)` — they propagate as ordinary mesh content, not chunked with the bundle, so the bundle itself stays small.
A "plugin directory" view aggregates: shows plugins seen on the mesh, queries reviews on demand. Acquiring a plugin from a direct peer:
chunked transfer of the bundle bytes, addressed as DM to the requester. Acquiring a plugin you've heard about but no direct peer has:
broadcast `PLUGIN_REQUEST(pluginId, version)`;
anyone holding it replies with either the bundle (chunked DM) or a metadata response "I have v5 and v7, not v6 — want those instead?" Requester chooses.
Versioning: every bundle carries `(pluginId, version)` in its manifest; old versions remain valid (no forced upgrades).
Authors push new versions by broadcasting a new metadata record;
users may subscribe to "notify me when new versions of plugin X appear." Reviews are pseudonymous (userId-signed) so a reviewer's track record across plugins is visible — a reviewer with consistently useful reviews becomes a trustable voice without any central authority.
