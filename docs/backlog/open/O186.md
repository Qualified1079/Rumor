# O186

**`[PART]`** O36 "the global feed is text-only — relay drops media before enqueue" — enforcement shipped; per-room media policy gated on O187

**Shipped (`27aed8a`, corrected `1259202`):** `MessageStore` drops any `ROOM_MESSAGE` with a plaintext `payload` whose `contentType != TEXT`, **before** the record-as-seen commit — deliberately, because `contentType` was outside the signed transcript when written (O212), so a relay could flip a genuine TEXT post to IMAGE;
burning the id would blackhole it downstream.
Now that O212 (G54) signs `contentType` the drop *could* move below the commit, but leaving it above costs only a re-offer.
ENCRYPTED room messages carry no readable contentType and are untouched (their media policy is the creator's, `RoomCreate.allowMedia`). Coverage:
`MessageStoreFeedMediaTest` (`:simulator`) plus `FeedTextOnlyEnforcementTest` (real transport, genuinely-signed attack message, TEXT control differing only in contentType;
asserts absence from the relay's store, a downstream node, and the relay's known-id set).
The 2026-10-11 away branch implemented a second, relay-side copy of this drop;
it was discarded at merge (2026-11-06) in favour of `main`'s, and its test kept because it passes against `main`'s implementation.
**Still open:** per-room `allowMedia` is unplumbed, so today the rule is unconditional for all plaintext room messages;
when media rooms ship it must become "drop unless this room's allowMedia permits, and ALWAYS for the feed", never be deleted.
The feed's own identity (hardcoded id vs well-known tag) is still an O154 decision. Cross-ref O36, O154, O155, O187, O212.
