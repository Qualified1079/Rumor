`routing/TopologyTracker.kt:78-87`:
the update branch of `recordSession` rebuilds `Route(...)` without `failureCount`, so it returns to 0 — the `bytesRelayed/(1+failureCount)` demotion lasts only until the next good session.
`recordSession`/`recordSessionFailed` are each get→build→upsert in separate `scope.launch`es (lost updates), and `recordSessionFailed` refreshes `lastUpdatedMs`, so a peer that only fails never ages out under `pruneStale`.
Class doc says stale routes are "not deleted" but `pruneStale` deletes them (→ O122).
**Fix:** carry `failureCount` (decay rather than reset), serialise per-peer updates, don't refresh the timestamp on failure.
