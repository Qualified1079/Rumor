# O67

**`[PART]`** Keyword filters as signed shareable lists**

**Rule: keyword filter lists are NOT blocklists** — distinct data type, semantics, and UI surface;
they share *only* the sign/verify/publish/subscribe distribution machinery from `BlocklistVerifier`. Don't conflate them in code or copy. Actions:
**WARN** (banner / collapsed-by-default) and **BLOCK** (never rendered locally — still relayed per the relay-never-touches-blocklist rule);
strictest label wins across merged lists; per-list `userIdAllowlist` exceptions (communities reclaiming terms, misclassified senders). **Default lists:
explicitly EMPTY at first launch (decision)** — users opt into community lists or author their own;
project signing key for any future bundled lists governed by `docs/PROJECT_KEYS.md`, reserved kind-id `rumor-project-default-lists-v1`.
Domain tag `rumor-keyword-filter-v1:`. **Shipped** (full detail archived in `docs/COMPLETED_GAPS.md`, O67 archive):
model + matcher + publisher + verifier + subscriber, repos + Room adapters (JSON-blob shape, schema v6) + DI + sim stubs, `MessageType.KEYWORD_FILTER_PUBLISH` gossip bridge (TRANSFER_SETUP class), 30 tests.
**Not done:** UI list editor (compose/edit/sign/share); auto-intake-by-publisher toggle (disclosed as "you are delegating filter decisions to <publisher>");
long-press "always show from this sender" exception UI;
honest-leak handling (subscribing advertises which lists you hold — accept as tradeoff vs per-list private mode); diff variant if real-world churn justifies it;
gossip-bridge tests with a real engine fixture. Required for App Store 1.2 UGC posture. The four content surfaces stay separate in UI:
text keywords (this row), image NSFW (O81), image gore (O81), sender identity (BlockManager/O78) — each with independent WARN/BLOCK.
