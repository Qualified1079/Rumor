# O30

**`[PART]`** Online-presence beacons**

Short-TTL INFRASTRUCTURE messages "I saw X within last N minutes" gossiped at low frequency. Lets peers far from X learn coarse reachability without polling.
Feeds O29's signal 11. Aggregated with recency decay. Privacy trade-off:
leaks "X was recently online and visible to someone in this mesh segment" — same leak class as DM `recipientId` today.
Should be capped (peer only beacons for contacts it has marked, not for every userId ever seen) and rate-limited so a malicious plugin can't flood.
**Refined per O58 design (self-presence only):** drop the "I saw X" variant;
the routing-decision value is small (presence doesn't tell you *which path* leads to X — breadcrumbs and bloom do), and beaconing someone else's presence without their consent is the heaviest leak in O58 Tier 3.
Replace with a **self-presence beacon**:
a Free-mode (or Static-mode) node says "I am running as infrastructure, I am online, here's my recent-exchange context" — same payload, sender opts into their own visibility, no third-party metadata.
The UX use case ("is Bob online?") falls back to local-only: each node infers presence from its own recent inbound from Bob (already Tier 1).
**Symmetric exit pulse required:** when a node leaves Static or Free mode (manual toggle off, unplug, screen-on transition), send a final "demoting myself" self-update so peers downgrade routing weight for this node immediately rather than waiting for stale signals to decay.
Without the exit pulse, DMs continue routing through ghost anchors for the full presence-decay window — minutes to hours of detours through a node that's no longer reliable.
