# O145

**`[TODO/HW]`** `WifiDirectTransport.stop()` permanently kills the singleton's coroutine scope (parallel audit, 2026-07-23; needs the fleet to verify)

**Confirmed by the 2026-07-23 audit, filed not fixed — this is field-verified O98 transport code and an unverifiable blind lifecycle change risks regressing hours of hardware tuning, so it wants a 3-phone session, not an overnight edit.** `scope` is a `val` (`wifidirect/WifiDirectTransport.kt:~62`);
`stop()` calls `scope.cancel()`; Koin registers the class as a `single`, so the same instance survives repeated `MeshService.startMesh()`/`stopMesh()` cycles.
Once the `Job` is cancelled it can't be revived — every subsequent `scope.launch{}` (accept loop, client round loop, GO-idle watchdog, priority watcher) is launched dead and **silently never runs**, no exception surfaced.
`TransportConfig`'s own KDoc documents "stop() then start() again after an identity change" as supported — it's broken. Compounding:
`stop()` doesn't reset `groupConnected`/`connectAttemptInFlight`/`discoveryInFlight`, and unregisters the broadcast receiver *before* `removeGroup()`'s disconnect broadcast arrives, so a live group at stop() can leave `groupConnected` stuck `true` forever, wedging `connectToPeer()`'s early return on all future attempts.
**Fix shape (verify on the fleet):** make `scope` a `var`, recreate it at the top of `start()`;
explicitly reset the mutable connection-state fields in `stop()`; reorder `stop()` to tear the group down before unregistering the receiver.
No `WifiDirectTransportTest` exists to catch a stop→start cycle — add one (even a JVM-level state-reset unit test) alongside.
Cross-refs O98 (backbone realization shares this instance), O93.
