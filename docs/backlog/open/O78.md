# O78

**`[TODO/CODE]`** Signed public block-reasons with ±1 attestations — visual rating only, no mechanical effect**

A user blocking someone may optionally publish a signed `BlockReason { blockedUserId, reasonText, reasonTags[], publishedAtMs }` (Ed25519 by the blocker), gossiped as INFRASTRUCTURE traffic.
Other users browsing a contact see "blocked by N users — top reasons:
spamming (38), harassment (12)" plus, more prominently, "**three of your regular contacts blocked this person**".
**±1 attestations** are sibling signed messages anchored to `(blocker, blocked, reasonHash)` so each signer can only ±/− a given reason once;
signature replay is impossible.
**This is a UI signal, not a filter input.** Visual highlighting only — contacts' ±1s render larger / brighter / labeled "your contacts";
stranger ±1s render small / aggregated; blocked-by-you ±1s render hidden or greyed.
**No mechanical filter behavior depends on counts**, so Sybil attacks against the count are irrelevant:
a bad actor +1-flooding their own block does nothing except inflate a number the display already devalues for stranger sources.
The earlier Sybil-mitigation analysis (graph-distance weighting, PoW, co-presence proof) is no longer needed because there's nothing to defend — the count is informational, not enforcement.
**Opt-in per-block** — default unpublished;
the publish toggle in the block UI surfaces the metadata-leak ("publishing this reason makes your identity visible to everyone seeing this contact").
**Account-deletion erasure:** O69's `IDENTITY_RETIRED` broadcast cascades to retract published BlockReasons + ±1s signed by the deleted userId;
peers honour and remove from local view. Old key is the proof.
**No quorum-of-third-parties erases someone else's content.** That remains a censorship primitive and explicitly off the table.
Cross-references O67 (signed list machinery — same publish/sign/diff), O68 (combined posture for App Store 1.2), O79 (Rooms also have block lists), O27 (deanonymization — published reasons are an opt-in identity leak by design).
