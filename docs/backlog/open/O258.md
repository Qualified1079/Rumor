# O258

**`[TODO/CODE]`** A relayed DM outside the freshest-200 offer window is never re-offered; RBSR by-id requests bypass the per-peer routing filter

Two leftovers from the 2026-11-11 catch-up fix, both about DMs, which that fix deliberately left alone.
(1) offerable() keeps the freshest N by sender clock across all types, so on a node holding more than 200 offerable messages a relayed DM from a slow-clock sender, or one that ties on timestamp, falls outside the window and is offered only once, from the destructive scheduler, to whichever peer opens a session first.
This is the likely cause of LanMeshHarnessTest.legitDmSurvivesAByzantineFloodOverRealWire failing about one run in five (the harness clock is frozen, so 250 flood broadcasts and the DM tie).
Direction: give DMs their own slice of the offer rather than competing with broadcasts on timestamp, keeping the per-peer routing filter.
(2) GossipSession serves any id a peer requests through messagesByIds, which returns stored DMs without the engine's intendedPeers filter, so above the RBSR threshold a peer can pull routed DMs the filter would have withheld.
Decide whether that filter is a privacy boundary (then enforce it on the by-id path) or a bandwidth optimisation (then say so in O58/O204).
