Seen live 2026-11-11: a node that was not a member posted to a MEMBER_ONLY room, the status page said posted, and every receiver dropped it (O89 check).
composeRoomMessage takes a routing tag and never consults the local roster, so the sender is told nothing.
The local roster can lag (an invite not yet arrived), so this is a UX honesty gap, not a security one: receivers enforce. Do:
when the tag maps to a subscribed room whose local roster says the sender is banned, or is not a member of a membership-required room, return null with a reason the UI can show.
Same family as O164 (UI reports success for something that went nowhere).
