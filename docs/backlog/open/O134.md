# O134

**`[TODO/CODE+UI]`** Peers list — every gossip peer auto-persists as a contact → sybil/ephemeral pollution; needs collapse-unnamed + search (filed 2026-07-22, user + live finding)

**Root cause (code):** `MessageStore.ensureContact` (`MessageStore.kt:175`) runs on ingest for **every** message's sender, so any peer whose message you ingest — including a one-shot sybil's SELF_PRESENCE or a relayed broadcast from a stranger — becomes a **permanent full contact**.
Live-confirmed: the sybil/oversize test left the OnePlus with **71 contacts, all 71 unnamed**.
A sybil swarm permanently pollutes the contact list (another O127 sybil cost beyond the presence-reply amplification).
**UX (user ask):** collapse un-nicknamed peers under a single "unnamed peers" header (expandable), and add a **search bar** to filter the peers/contacts list.
**Deeper design:** distinguish "known contacts" (DMed / manually saved / nicknamed / verified) from "seen peers" (gossip-exchange-only) — the list conflates them.
Options: (a) `ensureContact` writes a lightweight seen-peer record, promoted to a real contact only on real interaction (DM, manual save, nickname);
(b) keep the row but the peers UI filters/collapses by `displayName IS NULL` + `isVerified`/`alwaysSave` flags (schema already has them).
Prefer (a) — it also shrinks the O55 months-of-accumulation growth.
Cross-refs O110/O113 (contacts UI rework — do together), O111 (nicknames — a named peer leaves the collapsed group), O127 (sybil pollution), O131 (list perf — collapsing also helps the jank), O23 (contact-table growth is unbounded today, same family as O120 prune loops).
