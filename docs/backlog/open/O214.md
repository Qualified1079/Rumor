# O214

**`[DECIDED 2026-10-11 — user]`** Rooms are organization, not secrecy — plaintext default, optional encryption mode, invite-chain gated, amnesiac timers

**The settled shape, so it stops being re-derived.** Rooms are *filters over the same broadcast substrate the feed uses* (O154:
the OPEN-room mechanism IS the feed transport), so a room = routing tag + write authority + subscription.
Their job is **organization and spam remedy** (O36's logic: moving to a governed room is the remedy), NOT confidentiality.
**Decisions:** (1) **Plaintext by default.** Encryption is an **optional mode**.
**Granularity is an open sub-choice the user left open — "either per-channel or roomwide" — and is NOT yet decided.** Note for whoever picks it up:
`RoomPostingCert.channel` already exists, so per-channel is reachable, but it needs a per-channel config map where room-wide needs one field;
the house rule against premature abstraction argues for room-wide first unless the user wants per-channel from the start. Ask, don't assume.
(2) **Hard encryption stays in DMs** — that is where the real crypto story lives (O38 prekeys, O191 ratchet).
A room cannot offer group forward secrecy without MLS-style ratcheting, so it should not imply secrecy it does not have.
(3) **Membership is gated by a single-use invite link with the creator chain documented** — each member record stores who invited them, forming a tree traceable to the creator;
this IS O151's signed invite tree and makes subtree-prune bans possible.
(4) **Amnesiac messages at arbitrary per-room time lengths.** **REJECTED, with reasons (do not re-propose):** a *hard member cap* on encrypted rooms — an arbitrary number set on guesses about user behaviour, not derivable from anything;
and *bounding member betrayal* — out of scope, unsolvable, any member can archive.
**Honest-framing consequences that follow and must reach user-facing copy (O27):** retention bounds **device-seizure-later**, never member betrayal, and cannot be enforced on a device you do not control — it is hygiene, not secrecy;
retention shorter than the expected partition window silently becomes message loss under O55 store-and-forward, so the floor must exceed it;
and with plaintext rooms the **membership roster, not the content, becomes the primary leak** — who is in a room is often more sensitive than what is said there (the social-graph exposure O60 already concedes).
