**`[TODO/SIM]`** Limited onion routing for high-sensitivity DMs — source-routed through KNOWN contact-relays only (filed 2026-07-30, privacy workshop)

Full Tor-style onion routing is the mechanism O60 says Rumor structurally lacks, and it fights O59 (next-hop, not source routing) for good reasons:
onion source-routing needs the sender to KNOW a working path + each relay's pubkey in advance, but a gossip DTN has unknown/flapping topology (a committed onion path dies if any hop drops — multiplicative failure, no adaptive reroute) and no relay-key directory (Tor uses centralized directory authorities — against Rumor's model).
**The narrow version that fits:** a *limited* onion for high-sensitivity DMs only, source-routed through a few KNOWN contacts whose pubkeys you already hold (friend-to-friend Sphinx-style path), NOT strangers — sidesteps the key-directory problem entirely, accepts the reliability hit as the price of path privacy.
Trades adaptivity/reliability (O59's whole point) for hiding the sender→recipient link from on-path relays.
DMs route (not flood), so unlike broadcasts there IS a single path to onion. Sim:
measure the delivery-rate / latency cost of a fixed 2-3-hop contact-relay onion vs adaptive next-hop under churn — find whether the reliability hit is tolerable for the sensitivity gain.
Narrows the O60 Tor-gap without pretending to close it. Cross-ref O59, O60, O53, O58.
