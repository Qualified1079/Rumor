# O185

**`[TODO/CODE]`** Every inbound `ROOM_MESSAGE` triggers two blocking SQLite reads on `Dispatchers.Default` (filed 2026-07-30, audit #32)

`app/.../di/AppModule.kt:174-183` `RoomSubscriptionProvider` wraps `repo.getAll()` in `runBlocking`, called per-message from `GossipEngine.handleRoomMessage`.
Since `ROOM_MESSAGE` relays unconditionally regardless of local subscription (by design, like BROADCAST), a `ROOM_MESSAGE` flood forces two blocking DB round-trips per message on a thread pool shared with the rest of the app's coroutine work — a CPU/IO-starvation DoS, not scoped to Rooms.
Fix: cache/observe the subscription set instead of a per-message blocking read. Cross-ref O79.
