**`[TODO/CODE]`** Runtime plugin loading (DEX loader)**

Current plugins (Meshtastic, MeshCore) are compiled into the APK — not loadable at runtime. For a true mod scene, plugins need to be droppable files.
Two mechanisms that compose: (1) **DEX loader**:
a `.rumor` bundle (zip of `.dex` + a manifest) loaded via `DexClassLoader` at runtime — the mod-scene primary path, distributable via flash drive or chunked transfer over the mesh.
(2) **Bound-service APK**: a separately installed APK exposes a bound service;
Rumor binds to it by intent — good for plugins that need their own Android permissions (camera, contacts, location) since those are scoped to the plugin APK, not Rumor's process.
Both paths feed into the same `PluginContext` interface. The DEX path runs in Rumor's process with Rumor's permissions; the bound-service path runs isolated.
No central repository; the mesh itself is the distribution channel. **Pre-ship requirement**:
a static manifest declaration in the plugin bundle listing which `PluginContext` APIs it calls, shown to the user as a disclosure popup before enable — not a security control (a malicious plugin can lie), but informed consent.
