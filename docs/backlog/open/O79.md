# O79

**`[PART]`** Rooms — unified open / invite / password / closed-membership shape (subsumes O52; allowed by default per O36)**

Spec: `docs/O79_PROTOCOL_SPEC.md`; threat model: `docs/ROOMS_THREAT_MODEL.md`;
full shipped-substrate narrative archived in `docs/COMPLETED_GAPS.md` (O79 archive).
**Recorded decisions:** two room modes only — **OPEN** (plaintext signed broadcasts to a routing tag) and **ENCRYPTED** (multi-recipient envelope:
one AES body + N per-recipient key wraps; kick = omit from the next envelope's recipient list; per-message FS automatic;
**no shared room key, no ratchet** — collapses O89 to posting certs only; PASSWORD folds into ENCRYPTED via a password-derived membership token). Routing:
per-message HMAC tag on the wire, never plaintext roomId. Membership:
events-derived (signed event stream replayed, projection cache for O(1) lookups) — **an authored, signed, per-room append-only op-log with trivial merge, strictly separate from message ordering, NEVER state-resolved from the message DAG** (the Matrix-state-resolution inoculation;
binding for all remaining work). Channels-within-rooms: `payload.channel` metadata, UI-filtered; write perms deferred to O89.
Global room is text-only at the protocol layer (O36).
**Shipped:** wire vocabulary (`core/model/Room.kt` — membership/posting policy enums, RoomCreate/RoomInvite/RoomAction, domain tags `rumor-room-{create,invite,action}-v1:`), `MultiRecipientEnvelope` + codec with O39 zeroing, `RoomRoutingTag`/`RoomTagMatcher`, `MessageType.ROOM_MESSAGE` + relay + clampTtl, `composeRoomMessage`/`handleRoomMessage`, subscription persistence (schema v9) + real provider, simulator scenario (`RoomMessageScenarioTest` — caught a real emit-gating bug), 60+ tests;
Ed25519→X25519 receiver-side derivation closed via O91 (see G30 — `RoomEndToEndIntegrationTest` exercises real encrypt→decrypt), so OPEN and ENCRYPTED both work end-to-end at the protocol layer today.
**Not done:** events-derived membership projection cache (needed for sender-side recipient enumeration at compose time);
all UI (room screens, member roster, join/leave events); `MessageType.MENTION`;
moderator key rotation (manual-confirm-by-members flow — NOT the deprecated G9 shape); conflict resolution on contradictory mod actions (lean:
last-action-wins + public audit log); Room forks; author edit/delete policy (O40 + "allow author delete" policy bit).
**2026-07-19 audit §15 — no wire path for moderator actions at all:** `RoomActionKind`/`RoomAction` (`core/model/Room.kt:104-136`) have no corresponding `MessageType`, no `composeRoomAction`, no receive-side handler — so even a *legitimate* mod's kick/ban/remove has nowhere to go on the wire;
a kicked member's key keeps working indefinitely and nothing in the mesh can revoke them today (the enforcement gap pairs with O89's unwired posting-cert verify).
**REVISED 2026-07-24 (user direction):** the two-mode OPEN/ENCRYPTED split is reframed — OPEN (plaintext-to-routing-tag) is no longer a *room* mode but **the feed** primitive (O154);
every actual *room* is invite-gated and therefore **ENCRYPTED** as baseline (O155). The OPEN wire mechanism/code is retained as the feed transport, not removed.
The remaining authority/conflict/kick machinery in "Not done" is now specified across O148–O152 (+ `docs/MODERATION_AUTHORITY_RESEARCH.md`);
"Room forks" folds into the fixed-membership fork model (O147).
