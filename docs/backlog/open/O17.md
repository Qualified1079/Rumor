# O17

**`[PART]`** Extend bridged content beyond direct peers (`BRIDGE_VOUCHED` trust level)**

Today BRIDGED traffic is dropped on relay (see design decisions), so a bridge only reaches its direct Rumor peers — Charlie three hops away in the Rumor mesh never sees Bob's Meshtastic message even though Alice's bridge has it.
Proposed mechanism: introduce a third trust level between VERIFIED and BRIDGED, called `BRIDGE_VOUCHED`.
Bridge wraps the foreign message in a Rumor-signed outer envelope that explicitly carries `{originNetwork, originSenderId, originSignatureIfAny, payload}`.
The outer envelope is signed by the bridge's Rumor key — but the wire format and trust level make it unambiguous that the bridge is vouching for *delivery* only, NOT for content authenticity.
Other Rumor peers can relay it because the outer envelope verifies.
Display layer renders as "via Alice from meshtastic:Bob" with a distinct visual treatment from native Rumor messages.
Recipients decide per-bridge whether to trust that bridge's vouching (UI: enable/disable bridge-vouched relay per known bridge).
Replaces the current absolute "never relay BRIDGED" with a more nuanced "never relay BRIDGED without an authenticated outer envelope from a bridge node we know about." Scope:
new TrustLevel enum value, new wire envelope format, signature verification of outer envelope at every receiver, UI for per-bridge trust toggles, three-state visual rendering.
Real design work; not started.
