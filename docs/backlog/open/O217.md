# O217

**`[TODO/CODE]`** Encryption is a per-call caller choice, not a declared room mode (implements O214)

Today `composeRoomMessage` picks plaintext vs encrypted purely by whether the caller passes a non-empty `recipients` list (`GossipEngine.kt` ~1002:
`if (recipients.isEmpty())` → signed plaintext broadcast, else `MultiRecipientEnvelope`).
So two members of the same room can disagree about whether it is encrypted, per message, and nothing declares or enforces the room's intent.
O214 makes it a **declared room mode**, plaintext by default.
**Enforcement that makes the mode load-bearing rather than cosmetic, and the asymmetry is deliberate:** in an ENCRYPTED room a **plaintext** post must be REJECTED (it would be world-readable to anyone who can compute the public routing tag, defeating the mode for everyone);
in a PLAINTEXT room an *encrypted* post is harmless and should be allowed (a member choosing extra protection leaks nothing). Same shape as O186's feed rule.
