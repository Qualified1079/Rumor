# O230

**`[TODO/CODE]`** `LanTransport` start/stop has no generation token — failed start sticks, stop-during-start leaks, O166 cap loosens after restart (filed 2026-11-06; stop-path verified)

"Started" is `scope != null` (`core/transport/lan/LanTransport.kt:79-81`, non-volatile, written on IO).
**(a)** A bind failure is caught (:143) but leaves `scope` set, so `start()` early-returns forever until someone calls `stop()`.
**(b)** `stop()` during startup reads `jmdns`/`serverSocket` while still null;
the blocking `ServerSocket(...)`/`JmDNS.create` then complete, assign late, and are never closed — a dead node keeps advertising.
**(c)** `stop()` resets `inboundInflight`/`inboundPerSource`/`activePeerSessions` (:159-163) while old sessions are blocked in socket IO;
their `finally` later drives `inboundInflight` negative (raising the effective O166 32-session cap by the number of stale sessions) and can remove a claim the new generation made for the same peer.
**(d)** Per-peer round loop:
after `MAX_ROUND_FAILURES` the loop removes itself (:216) and the peer is gone for good, since JmDNS doesn't re-resolve a still-advertised service;
and a session that yields to a duplicate (GossipSession returns null) counts as a failure.
**Fix:** explicit `Stopped/Starting/Listening/Failed` + an epoch captured by each session and checked in `releaseInbound`/claim removal;
failed loops back off instead of terminating. Security-relevant via (c).
