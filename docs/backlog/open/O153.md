# O153

**`[TODO/SIM]` `[DECISION]`** Endpoint-aware forwarding — gossip-at-edges / tree-multicast-on-backbone; large rooms should be OPEN — filed 2026-07-24

The "route a message to X,Y,Z at the mesh edges" idea:
within one Wi-Fi Direct cluster, endpoint-aware unicast fan-out CANNOT beat broadcast (shared CSMA channel — dupes O102's negative result);
one link-layer broadcast overheard by all neighbors is already optimal, which gossip exploits.
Structured multicast (Steiner tree) only wins across genuinely-parallel channels (inter-cluster / backbone / LoRa), and building that tree needs "which cluster holds which member" = the O58-Tier-3 topology leak — so confine tree-multicast to the O98 backbone where that visibility is already accepted;
edge/mobile nodes stay pure-gossip.
A wrap-set-by-region optimization (a backbone link carries only the O79 envelope wraps for members downstream of it) rides on top.
**Key reframe:** a 1000-member ENCRYPTED room's cost is the *envelope* (~48 KB = 1000 key-wraps), NOT propagation — routing can't shrink it;
and at that scale confidentiality is illusory (1-of-N leaks it), so **large rooms should be OPEN/feed-shaped** (one small signed broadcast to a routing tag, gossips cheaply) and endpoint-aware routing is moot for the case that actually scales.
