# O231

**`[PART]`** Receive-side transfer lifecycle is still five unsynchronised stores — pause/watchdog contradiction, restart recovery, no CAS (filed 2026-11-06; the hash-mismatch wedge + cancel guard closed as G68)

State is `TransferRecord.status` + in-memory `watchdogs`, `activeBySender`, `paused`, `chunkHashesByTransfer` (`core/transfer/TransferAssembler.kt`).
**Remaining:** **(a)** pause drops chunks at ingest but the watchdog keeps NACKing and burns retries to ABANDONED within ~5 backoffs;
**(b)** none of the in-memory maps survive restart — a stalled IN_PROGRESS row never gets a watchdog again and the per-chunk hash check is lost;
**(c)** `TransferRepository.updateStatus` has no compare-and-set, so concurrent writers (cancel vs reassembly) can still overwrite each other — G68's in-process `reassembling` guard covers ingest-vs-watchdog only.
**Fix direction:** one explicit per-transfer state with guarded transitions, `updateStatus(from, to)`, and a startup sweep that re-arms or terminates stale IN_PROGRESS rows.
Harness: `TransferAssemblerTest` (`:core`), `TransferAssemblerHardeningTest`/`TransferNackWatchdogTest` (`:simulator`).
