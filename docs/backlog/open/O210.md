# O210

**`[DECIDED 2026-10-10 — SHIP]`** Rooms ship in v1 (user decision)

**Decision: ship.** Rationale (user):
without governed rooms *everything is public spam* — which is also O36's own logic, that moving to a governed room IS the spam remedy.
Shipping only the ungoverned text-only feed (O154/O186) therefore ships the failure mode FireChat died of; the feed is the thing rooms exist to escape.
An earlier session recommended cutting, weighing O79's wire-format risk;
that weighed the wire risk correctly and the product risk not at all, and is superseded. **Consequence, which the cut-recommendation already named:
O89 and O187 are now hard release blockers,** because a room that *looks* governed while write authority is unenforced is worse than no room — it invites exactly the trust the mechanism cannot honour.
**Ship order:** (1) **O89 write enforcement** first — security-critical, pure `:core`, no device (`RoomPostingCertVerifier` currently has zero production call sites;
`composeRoomMessage` attaches no cert and `handleRoomMessage` performs no authority check, so any client can post to any room whose routing tag it knows);
(2) **O187** RoomRepository + Create/Invite/Action wire transport; (3) **O185** drop the two `runBlocking` SQLite reads per inbound ROOM_MESSAGE.
O186 (feed text-only) already shipped.
O148/O149/O151/O152/O154/O155 remain open design and do NOT block v1 — but anything that touches the signed wire shape should land before release, not after, since `docs/RENAMED_FIELDS_NEVER_REUSE.md` makes field names permanent.
