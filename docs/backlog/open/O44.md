# O44

**`[TODO/EMU]`** Keystore wrapping-key architecture (refines O20)**

Don't put the raw Ed25519 private directly in Android Keystore — it's non-exportable by hardware contract, which breaks every backup path. Instead:
generate an AES-256-GCM wrapping key in Keystore (`setUserAuthenticationRequired` if biometric available, `setUnlockedDeviceRequired(true)` minimum, `setIsStrongBoxBacked(true)` on supported hardware).
The Ed25519 private key lives encrypted-at-rest in app storage; decrypted into memory only inside `signWithLocalKey()`, zeroized on exit.
Plugin context exposes `signWithLocalKey(bytes)` only — never a raw-key accessor; DEX plugins cannot exfiltrate.
Surface `KeyInfo.isInsideSecureHardware()` in the UI so users know whether their device has hardware-backed protection or fell back to software Keystore.
**Platform-fork note (2026-07-15, O106):** this whole row is Android-only by nature — the desktop/USB node gets a file-based encrypted identity impl behind the same `IdentityProvider` interface instead.
The identity-at-rest story forks per platform by design; don't try to unify it.
