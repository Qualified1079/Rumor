# O192

**`[TODO/CODE]`** Key-retirement / compromise beacon — signed "stop trusting this key" broadcast (filed 2026-07-30, privacy workshop)

NOT identity continuity (rejected — an attacker holding the stolen key can also sign a successor, so continuity-after-compromise is theater).
Instead a signed broadcast in two flavors: **abandoned** (soft: "stop using this key") and **compromised/stolen** (hard:
"distrust this key, retroactively too"). Two honest limits baked in:
(1) you CANNOT cryptographically date the theft — an attacker with the key can backdate any message, so "distrust everything after time T" is unenforceable;
the beacon is necessarily the blunt "distrust this key, period." (2) **Pre-sign it at identity creation** and store the trigger, so you can fire it under duress even after losing the key — which is exactly why it wires to the O189 "explode" duress passphrase (if the attacker has your key and you don't, pre-sign + duress-trigger is your only window;
a live attacker won't retire their own stolen key for you). Contacts holding the old pinned key (O21) honor the retirement;
new-message auth from the retired key is refused. Cross-ref O189, O21, O191.
