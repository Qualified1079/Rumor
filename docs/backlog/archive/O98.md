Original design notes below.
— Wi-Fi Direct caps how many peers one device can hold in a persistent group (GO client limit / concurrent-P2P limit — small, ~8–10 and hardware-dependent).
Naive "everyone persists with everyone" is impossible past the cap and thrashes:
an apartment building of 20 people who all want to stay connected produces continuous drop-churn as each device round-robins its slots. Smart persistence:
instead of all-to-all, compute a **connected covering overlay** over the persistence graph — a set of held links (think spanning tree / connected dominating set) such that every member is reachable multi-hop through *someone's* held links, while no device exceeds its degree cap, and total churn is minimized.
Person 1 reaches person 20 as long as the union of held links forms a connected backbone with minimal overlap. Design surface:
(a) each node advertises its remaining persistence capacity;
(b) a distributed (or GO-coordinated) decision picks which links to hold so the backbone stays connected as members join/leave — degree-bounded connected dominating set is the model, but it must be *incremental* (adding one member shouldn't reshuffle the whole backbone) and *stable* (hysteresis so a flapping peer doesn't reorganize everyone).
Integrates tightly with O57 modes (Free/Static plugged-in nodes are the natural high-capacity backbone anchors — give them higher degree budgets and prefer them as dominators), O29 breadcrumb routing (the backbone *is* the routing substrate), and G19's known "held group starves discovery of a third phone" limitation (smart persistence is the general answer:
hold the backbone links, time-slice the rest). Prerequisite thinking:
the cap is per-device and asymmetric (a plugged-in tablet can hold more than a pocketed phone), so the objective is degree-**bounded** per node, not uniform.
Non-trivial distributed-algorithms work; start with a GO-coordinated centralized solver per group and generalize later.
**Channel selection (absorbed from O99 — do it here, don't add a separate feature):** every backbone host must bring up its group via autonomous `WifiP2pManager.createGroup(channel, WifiP2pConfig.Builder().setNetworkName("DIRECT-…").setPassphrase(…).setGroupOperatingFrequency(quietFreq).build(), listener)` — **field-verified (2026-07-13, Moto+OnePlus+Samsung) as the ONLY path Android honors the operating channel on.** A negotiated `connect()` *ignores* `setGroupOperatingFrequency` (all three phones formed on ch36/40 regardless of the requested channel);
autonomous `createGroup` *does* honor it (OnePlus formed on the requested ch149, Samsung on ch153).
Pick `quietFreq` by scanning `WifiManager.getScanResults()` (location already held) for the least-congested non-DFS 5 GHz channel — candidate freqs 5745/5765/5785/5805/5825/5180/5200/5220/5240 MHz, UNII-3 first since consumer routers default to the low UNII-1 channels.
Why it matters: a P2P GO on the driver-default ch36 collided with a bystander's 5 GHz and dropped it;
Wi-Fi is CSMA/CA so this is contention + STA channel-switch churn on a *marginal* link, not RF jamming — a channel-selection problem.
Prefer 5 GHz (more non-overlapping channels, smaller footprint, keeps 2.4 GHz free for BLE);
if the air is saturated, land CO-channel with the strongest neighbor (CSMA shares) rather than adjacent (un-arbitrated overlap, worse).
**Two blockers this makes O98's problem, not a quick win — both observed during the O99 spike:** (a) `createGroup` groups need a manual WPS invitation-accept to join on some devices (OnePlus hosted on ch149, Moto would NOT auto-join, 0 sessions) — the backbone needs **prompt-free joins**, e.g.
a deterministic pre-shared networkName+passphrase both peers derive (from the pair's userIds) so clients join as a legacy STA without WPS PBC;
(b) electing hosts from asynchronous discovery views **fragments** (two devices each self-elected host → three groups, zero sessions) — convergent, member-cap-aware host election is exactly this row's backbone computation.
Samsung API 31 also rejects the Builder unless a networkName is set (createGroup provides one, so that path is fine).
A standalone pairwise prototype was built and reverted (proven-ineffective connect() hint + WPS-blocked joins) — channel selection is only coherent as part of the backbone here.
