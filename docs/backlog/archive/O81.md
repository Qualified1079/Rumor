**`[TODO/CODE]`** Local-only on-device image content classifiers — NSFW (still + video), gore (video; still TBD) as shipped-default LOCAL_ONLY plugins**

**Image-content companion to O67 (text-pattern filter).** Two surfaces covered separately — NSFW (sexual content) and gore (graphic violence) — each its own classifier, each its own user-facing WARN/BLOCK control.
**Shipped out of the box** as LOCAL_ONLY plugins (O24):
cannot reach the network, cannot register a DM envelope, cannot compose outbound messages — loader denies.
Cannot leak the user's images anywhere by construction. Runs on every inbound IMAGE-type message before display; sets per-message `contentWarning:
{ nsfw, gore }` flags the UI consumes.
**WARN vs BLOCK are orthogonal user controls:** WARN = blurred-thumbnail-with-tap-to-reveal plus label ("contains sexual content" / "contains graphic violence");
BLOCK = never display the image, drop the attachment locally. Default-WARN for both at first install; promotable to BLOCK per-surface during onboarding.
**Stacking / strictness slider:** user can enable multiple classifiers per surface and combine with `any-flags ⇒ flag` (OR) or `weighted-sum ⇒ flag if score > threshold`.
UI slider: `off / high-confidence-only / moderate / anything-flagged`. Default: lightest model only (cheapest APK cost);
user opts into stacking heavier/stricter via slider.
**Per-surface model status (research per `docs/RESEARCH_NOTES.md` §8):** **NSFW stills:** (a) **AdamCodd/vit-base-nsfw-detector** (HuggingFace, Apache 2.0) — ViT-based, ONNX export available, more accurate than Open NSFW, recommended default.
(b) **Yahoo Open NSFW** via `tensorflow-open_nsfw` → TFLite (BSD 3-Clause), ~22 MB, model from 2016, acceptable as a stackable second opinion.
(c) **NudeNet v3** ONNX (Apache 2.0), granular body-part detection, best accuracy, requires Kotlin/ONNX-runtime port.
**NSFW video:** MobileNet-TSM single-frame mode on key frames as a stopgap. **Gore stills:
research gap — no production-ready open-source classifier verified.** Three fallbacks until a real still-gore model emerges:
(i) MobileNet-TSM single-frame inference (degraded accuracy), (ii) Roboflow community-trained models with disclosed accuracy caveats, (iii) text keyword filter via O67 as the only ship-able default.
Ship gore-still as "WARN-via-keywords-only until classifier matures" with honest disclosure.
**Gore video:** **MobileNet-TSM** (PMC9621415, paper-bundled GitHub source + trained model + Android demo), ~8.5 MB, real-time on-device, uses temporal frames.
**Recommended starting bundle:** AdamCodd ViT (NSFW stills) + MobileNet-TSM (NSFW + gore video) + O67 keyword filter (text + gore-still fallback).
Combined ~30 MB. **Model distribution is post-install P2P, not bundled in the APK** — keeps install size slim and lets users opt into specific classifiers.
On first launch (or first inbound image), prompt user to download whichever classifiers they want.
Models are signed blobs (publisher pubkey + version + SHA-256 + capability declaration).
Once one peer has a model, others request it over the mesh via the same chunked-transfer path as O26 plugin sharing;
the mesh itself is the distribution channel.
Cold-start fetch via plain HTTPS from a published mirror (model author's site, IPFS, GitHub releases) is the only network exception, and only on user-initiated install — after that, mesh re-distribution covers updates.
Model verification: same signing infrastructure as plugins (O26 community attestation), with publisher key pinning on first install.
Bundled APK installs zero classifiers by default; user explicitly opts in.
**Explicit non-decisions:** (1) **Never** Google SafetyCore (system-service, Play-Services-adjacent, breaks F-Droid posture per O56).
(2) **Never** Firebase AutoML even though `nipunru/nsfw-detector-android` uses it — same posture violation. (3) **Never** any cloud-API fallback.
**Update model on plugin update only** (no runtime download — that would be a network leak).
**Pre-ship requirements:** model card published per classifier (training data sources, known biases incl.
demographic error-rate gaps — Open NSFW has documented issues with darker skin tones; surface in onboarding copy honestly);
on-device-only enforcement at LOCAL_ONLY plugin tier verified by loader; capability disclosure popup before enable (O15).
Cross-references O24 (LOCAL_ONLY plugin tier — canonical use case), O67 (text-pattern sibling and the only stills-gore filter until a model matures), O68 (combined App Store 1.2 posture), O56 (no Google system service dependency).
